Authoritative orientation for coding agents (GitHub Copilot, Claude Code, Codex, Cursor, Amp, Factory, etc.) working in this repo.

Companion: `CLAUDE.md` (thin pointer to this file) and `.github/copilot-instructions.md` (thin pointer to this file). Treat this file as canonical.

## What this repo is

Two artifacts in one tree:

1. **Polyphony CLI** (`src/Polyphony/`) — a .NET 11, AOT-compiled CLI that exposes ~24 verbs across 9 command groups. It does deterministic SDLC routing — phase detection, transition validation, branch-name resolution, policy queries — and emits structured JSON. It writes nothing to Azure DevOps; all writes are delegated to [`twig`](https://github.com/PolyphonyRequiem/twig).
2. **Conductor workflow suite** (`.conductor/registry/workflows/`) — the YAML files driving `conductor` (a multi-agent orchestrator). The `polyphony@polyphony` workflow is the canonical SDLC entry point.

The CLI and workflows ship from the same repo so they version together. They are independent artifacts.

See `README.md` for the operator overview and `docs/concepts/polyphony-architecture.md` for the layering model.

## Build, test, lint

Run from the repo root.

### CLI
```powershell
dotnet build src\Polyphony\Polyphony.csproj -c Release
```

### Tests (full suite)
```powershell
# 1. Refresh the verb-output-schemas registry if you changed verbs:
dotnet build src\Polyphony.SchemaExporter\Polyphony.SchemaExporter.csproj -c Release

# 2. Build tests, then run with --no-build:
dotnet build tests\Polyphony.Tests\Polyphony.Tests.csproj -c Release
dotnet test tests\Polyphony.Tests\Polyphony.Tests.csproj -c Release --no-build
```

The `Polyphony.SchemaExporter` build regenerates `artifacts/verb-output-schemas.json` via an AfterBuild target. Several tests (especially `VerbCatalogSanityTests`) require this artifact.

### Lints
See `.github/workflows/ci.yml` for the full list. The most commonly broken:
- **Vocabulary lint** (forbidden-terms gate from AB#3259 / docs/glossary.md):
  ```powershell
  .conductor\registry\tests\lint-vocabulary.ps1 -Root .
  ```
- **Jinja2 resolver lint** (workflow YAMLs use only registry-known result fields):
  ```powershell
  pwsh -NoProfile -File tests\lint-jinja-resolver.ps1 -Format github
  ```
- **Type-agnosticism lint** (no work-item-type names in routing conditions):
  ```powershell
  pwsh -NoProfile -File tests\lint-type-agnostic.ps1 -Surface all
  ```

## Do not edit by hand

| Path | Why |
|---|---|
| `artifacts/` | Gitignored. Build outputs. Regenerate via `dotnet build`. |
| `tests/lint/fixtures/verb-output-schemas.json` | Locked snapshot fixture. Refresh by copying the live `artifacts/verb-output-schemas.json` over it after verb changes — never hand-edit. |
| `.polyphony-state/`, `.polyphony/` | Gitignored. Local per-root run state. If they reappear in `git status`, they are stale — never commit. |
| `.twig/` | Gitignored. Per-machine twig CLI state. |

Anything generated by `Polyphony.SchemaGenerator` / `Polyphony.SchemaExporter` is regenerated from the source verb classes. Touch the source, rebuild.

## Cardinal rules

1. **Vocabulary discipline.** `docs/glossary.md` defines the canonical terms. Forbidden synonyms (e.g., `apex`, `wave`, `cascade`, `primary_*`) are gated by a lint. AB#3259 was a hard cut — there are no aliases.
2. **Type-agnosticism (P5).** No work-item type name (Epic / Issue / Task / Bug / etc.) may appear in any routing condition. Types live in consumer-repo `.polyphony-config/work-item-types/`. This is a load-bearing invariant, not a hygiene preference.
3. **No writes from polyphony.** The CLI is read-only against ADO. All writes are delegated to twig.
4. **Three vocabularies.** Workflow YAMLs use three distinct vocabularies: **events**, **state names**, **categories**. Never confuse them. See `docs/concepts/polyphony-architecture.md` "The three vocabularies".
5. **Cite by `path:line-range`.** When skill docs or PR descriptions reference source, use `path:line-start-line-end` so future agents can verify.
6. **Pair work-item IDs with summaries.** When mentioning `AB#NNNN`, include a brief title or description in the same sentence so the reader has context without looking it up.

## Cross-platform invocation

This repo is developed primarily on Windows (PowerShell 7+). CI runs on Linux. Scripts and YAMLs are expected to work in both environments.

- Prefer `pwsh -NoProfile -File <script>` over `pwsh -Command`.
- Avoid bash-isms in shared scripts (use `Join-Path`, `Test-Path`, etc.).
- Workflow YAML `script:` nodes invoke a shim that runs on both platforms.

## Where things live (one-line tour)

- `src/Polyphony/` — the CLI.
- `src/Polyphony.SchemaGenerator/` — Roslyn source generator for verb output schemas.
- `src/Polyphony.SchemaExporter/` — at-build-time exporter that writes the JSON registry.
- `tests/Polyphony.Tests/` — xUnit tests.
- `tests/lint/` — Pester tests and lint scripts.
- `.conductor/registry/workflows/` — conductor workflow YAMLs.
- `.conductor/registry/scripts/` — PowerShell helpers invoked by workflows.
- `.conductor/registry/tests/` — workflow lint tests (Pester).
- `.github/skills/` — agent skills (auto-loaded by the Copilot CLI / Claude Code).
- `.github/workflows/` — GitHub Actions CI.
- `docs/` — human + agent documentation. See `docs/README.md`.
- `scripts/` — operator-facing PowerShell launchers (e.g., `Invoke-PolyphonySdlc.ps1`).
- `workflows/` — workflow author docs (README pointing at registry workflows).
