- 📌 CARDINAL TRAP: `[System.IO.File]::ReadAllText` with a relative path uses `[Environment]::CurrentDirectory` (NOT `$PWD`). After `cd worktree-dir`, sync them with `[Environment]::CurrentDirectory = $PWD.Path` or use absolute paths. Otherwise scripts read from the .NET process's original cwd and silently overwrite target files with stale content.
- 📌 `Invoke-PolyphonySdlc.ps1` runs `twig show <RootId>` in cwd before init-root. The cwd's twig workspace/cache MUST contain the root item.
- 📌 PowerShell `&&` only chains native/external commands. Do NOT use `&&` before pwsh keywords (`if`, `foreach`, `$var =`). Use `;`.
- 📌 NEVER use `git -C {path}` in scripts (unreliable on Windows). `cd` into the dir first, then run git.
- 📌 NEVER embed newlines in `git commit -m "..."` (backtick-n fails silently in pwsh). Write the message to a temp file and use `git commit -F $msgFile`.
- 📌 `.conductor/registry/tests/*.Tests.ps1` is NOT auto-discovered by ci.yml — new Pester test files need explicit CI workflow wiring.
- 📌 Each polyphony worktree has its OWN `.twig/` workspace config inherited from origin/main at creation. Per-worktree edits don't propagate to other worktrees; commit area-path fixes in the worktree to satisfy assert-clean.

- 📌 STRICTMODE + PSOBJECT TRAP: Under `Set-StrictMode -Version Latest`, accessing any property not on a PSCustomObject throws PropertyNotFoundException immediately — before catch chains. A `List[hashtable]` via pipeline: empty → `$null`, 1 item → bare hashtable. Always wrap call-site in `@()`; avoid `[System.Collections.Generic.List[T]]` parameter type hints (binding a plain hashtable throws StrictMode during argument conversion).
- 📌 CONVERTFROM-JSON DATETIME TRAP: `ConvertFrom-Json` silently promotes ISO-8601 strings (`"2026-05-29T19:23:00Z"`) to `System.DateTime`. In Pester, `Should -Match` then runs against `DateTime.ToString()` (locale format). Normalise with `if ($v -is [datetime]) { $v.ToUniversalTime().ToString('yyyy-MM-ddTHH:mm:ssZ') }` before regex assertions on timestamp fields.

- 📌 2026-05-31T10:51:14-07:00: Wrote conductor gaps report (`.squad/handoffs/liszt-conductor-gaps-20260531.md`). Top 2 gaps for Daniel: (1) Missing `on_error:` in route tables — both github-pr.yaml and ado-pr.yaml carry TODO(AB#3257) for this; until it ships, infrastructure failures (auth, network) crash the run without a recovery gate. (2) No between-invocation state primitive — scripts invent file-based watermarks in `$TEMP` that break across machine boundaries and reboots.
- 📌 CONDUCTOR `on_error:` GAP: `script:` nodes have no `on_error:` key in `routes:`. Non-zero exit codes surface as unhandled conductor ExecutionErrors, not as routable workflow conditions. Until AB#3257 ships, all infrastructure failures must be absorbed into exit 0 + `error` field in JSON output, or the run dies. The AB#3257 fix proposal: `on_error: - to: <step> when: "{{ script.exit_code == N }}"`.
- 📌 BETWEEN-INVOCATION STATE GAP: Conductor has no storage primitive (no `type: store` node, no `state:` section). Scripts implement file-based watermarks in temp dir (`Join-Path ([System.IO.Path]::GetTempPath()) "conductor-pr-delta-$pathKey.json"`). This breaks on machine-boundary (distributed conductor), on reboot, and has no TTL. The initial-observation re-entry loop (extra conductor iteration per poller startup) exists solely because there's no "if first run" primitive.
- 📌 SCRIPT NODE CONTRACT GAPS: Conductor does not document: stdin disposition (closed? open?), stdout parsing (last JSON object? full buffer?), cwd of the launched process, env var inheritance, or kill semantics on abort/timeout. All these were inferred from existing scripts. `workflow.dir` is critical (used in every `-File {{ workflow.dir }}/../scripts/...` arg) but undocumented.
- 📌 `CONDUCTOR_ERROR_OUT` is an undocumented convention invented in Poll-PrStateDelta.ps1 — scripts write a structured error JSON to this env-var path on non-zero exit. Conductor does not officially set this variable; the `if ($errOut)` block is dead code on real conductor runs today. Useful once conductor officially supports it + once `on_error:` ships.
- 📌 BLOCKING SCRIPT TIMEOUT GAP: Conductor has no `timeout_seconds:` on `script:` nodes. Long-running scripts (like Poll-PrStateDelta's 24h poll loop) have no cooperative-cancellation contract. The graceful abort path uses `abort-run.ps1` which POSTs to `/api/stop` — conductor's InterruptError fires at between-agent checks, but does NOT kill the blocking child process mid-sleep.
- 📌 SHELL-OUT IDIOM REFINED: Use `command: polyphony` directly when output IS the verb's JSON. Use inline pwsh (`-Command`) for ≤15-line self-contained logic with no tests. Use a helper script (`-File scripts/Foo.ps1`) whenever: logic needs Pester tests, state persists across invocations, operation blocks >a few seconds, error classification is non-trivial (multiple exit codes), or the same logic is shared across workflow YAML files. Helper scripts take named params, not template-expanded args — keeps Jinja surface small and test harness clean.
